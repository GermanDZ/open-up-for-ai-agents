- **Iteration 98** (2026-07-27): T-140 (standard) — **run-log records no longer dirty the tree, so no lane pays a sweep commit**. The roadmap offered two directions; direction 1 ("stage-then-commit — write the shard pre-commit so it lands in the triggering commit") turns out to be **unimplementable**: the record carries the commit's SHA and the SHA hashes the tree that would hold the record, so a commit can never contain its own log record (`--amend` invalidates the SHA the record just wrote). What *is* implementable is staging the records of all **prior** commits. So the write is split in two: `auto-log-commit.py` (PostToolUse) now queues to the untracked `<main-root>/.openup/run-log-pending.jsonl`, and a new `stage-run-log.py` (PreToolUse) drains that queue into each record's **own** lane shard and `git add`s it immediately before the next commit — records land *inside* a commit, the tree is never dirty, steady-state lag is exactly one record (the trailing one, drained by the next commit anywhere). Queue lives in the **main** checkout, not the lane worktree, so the trailing record survives `/openup-complete-task`'s worktree teardown. Drain logic sits in `scripts/openup-runlog.py` (argv-list subprocess calls, no shell) so it is unit-testable without a hook harness. **Pathspec-limited commits deliberately do not drain** — `git commit -- <paths>` would ignore the staged shard and leave it staged-but-uncommitted, recreating the very defect; unparseable commands skip too (safe direction). The three places prescribing the manual sweep are gone: `conventions.md` §Pre-Commit Housekeeping now says "nothing to do", `/openup-complete-task` step 2 dropped the fold-in instruction, and the hook docstring was rewritten. **Known deployment note (verified live, DD5):** `CLAUDE_PROJECT_DIR` resolves to the main checkout and hooks run from its gitignored `.claude/scripts/hooks/`, so the fix only takes effect once `scripts/sync-templates-to-claude.sh` runs on main after the merge — until then the old hook still fires (this lane contains one final legacy sweep commit as evidence). Six existing `test_t006_hooks.py::AutoLogCommitTests` cases asserted the old shard-write contract and were updated to queue-then-drain (not weakened — they now also assert the post-commit hook leaves the shard untouched). +36 new tests across `test_openup_runlog.py` (drain logic: routing, SHA dedupe, corrupt lines, pathspec parsing, fail-open) and `test_run_log_hooks.py` (both real hooks end-to-end against throwaway git repos: queue-not-shard, drain+stage, record inside the commit, logs-only skip, failed-commit skip, fail-open).
